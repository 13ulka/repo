# SceneForge — план (v1, согласован 2026-09-24)

Дата исследования: 2026-09-24. Машина: M4 Max (16 CPU / 40 GPU), 64 GB, macOS 26.6, Blender 5.2.2 LTS, ComfyUI 0.33.0, ffmpeg 9.0.1, uv 0.12.
Входы: `Room RUMI.mkv` (24 с, ~5 планов) и `Room RUMI 2.mkv` (115 с, ~7 планов), оба 1920×1080 @ 23.976, h264.

Легенда достоверности: **[V]** — проверено по репозиторию/PyPI (код, LICENSE, дата коммита); **[U]** — вторичный источник или вывод; **[T]** — нужно проверить прогоном на твоём Mac. Ни одна модель ещё не запускалась на M4 Max — все цифры времени/памяти ниже являются оценками.

---

## 0. Реалистичность: что меняется из-за исходников

1. **Это стилизованная CG-анимация, а не съёмка.** Плюсы: нет шума, motion blur слабый, геометрия «чистая». Минусы:
   - плоские toon-заливки дают мало текстурных фич → риск для сопоставления (особенно COLMAP/SIFT);
   - монокулярная глубина на стилизации менее надёжна;
   - «материалы из кадров» = albedo с запечённым toon-освещением, а не PBR. В Blender это будут в основном emission/unlit-подобные материалы. Физически честная переосвещаемость — отдельная задача, в MVP её нет.
2. **Анимационный фильм не гарантирует единую геометрию комнаты между планами.** В анимации предметы «читерят»: мебель сдвигают под ракурс, меняют фокусное, иногда декорация плана не совпадает с соседним. Поэтому в Stage 1 вводится **проверка согласованности планов**: план, который не регистрируется в общую систему координат, исключается и попадает в отчёт, а не ломает всю сцену.
3. **Несколько планов и персонажи.** Склейки — норма (не предупреждение). Персонажи маскируются **до** геометрии (Stage 0b), иначе размажутся по облаку.
4. **Длительность.** 139 с суммарно → берём не подряд, а ~150–300 ключевых кадров (адаптивно по движению камеры и резкости).
5. **Что на Mac недостижимо локально (честно):**
   - качественные splat→mesh методы (2DGS, PGSR, GOF, MILo) — только CUDA [V/U] → заменяем на TSDF fusion (Open3D);
   - novel-view/3D-consistent inpainting (SEVA, ViewCrafter, InFusion) — только CUDA [V] → заменяем на «рендер вида из Blender → 2D-inpaint → обратная проекция»;
   - nvdiffrast — CUDA [U] → Mitsuba 3 (есть Metal-бэкенд с 3.9.0 [V]).
   Для всех трёх предусматривается адаптер `remote` (ssh на CUDA-машину), но в MVP он не нужен.

**Что предлагаю урезать в MVP:** (а) дифференцируемую оптимизацию материалов — только позы/масштаб объектов + яркость/экспозиция; (б) оценку освещения — одна environment-лампа + 1–3 area-источника, подобранные оптимизацией, без DiffusionLight; (в) USD — опционально, через экспорт Blender.

Порядок в Stage 1:
1. MapAnything на всех ключевых кадрах всех планов разом (маскированные пиксели персонажей = 0, `apply_confidence_mask`).
2. Проверка согласованности: reprojection-ошибка и перекрытие облаков по планам → исключение несогласованных.
3. Опционально `--refine colmap`: bundle adjustment в pycolmap с позами от MapAnything как инициализацией.
4. Масштаб: VLM + SAM 3 ищут якоря (дверь ≈ 2.0–2.1 м, кровать, стол ≈ 0.75 м, потолок ≈ 2.4–2.7 м) → медиана оценок. Рост персонажей **не** используется: пропорции стилизованы. Если якорей < 2 или разброс > 20 % — CLI останавливается и спрашивает.

Выход: `points.ply`, `cameras.json` (intrinsics, extrinsics, план, кадр), `depth/*.npz`, `conf/*.npz`, отчёт о регистрации планов.

### Stage 2 — segmentation & objects
- SAM 3.1 (mlx-vlm): кандидаты объектов по текстовым промптам (список классов предлагает VLM по кадрам) + трекинг внутри планов.
- Связка треков между планами: 3D-ассоциация через лифт масок в облако (пересечение объёмов) + DINOv2-дескрипторы.
- VLM: **Qwen3-VL-8B (4-bit MLX)** через LM Studio (`lms server start`, OpenAI API), альтернатива Gemma 4 (Apache). Классы, `structure`/`props`, style card.
- Структура: RANSAC plane fitting (Open3D) по точкам классов wall/floor/ceiling → Манхэттен-выравнивание → «коробка» комнаты с проёмами окон/дверей.
- Для объекта: мировой OBB, список кадров, покрытие ракурсов (угловой разброс), доля видимой поверхности, качество 0–1.

| Рендер splats в Python (глубина для TSDF / проверки) | gsplat-mlx | Apache [V] | ✔, молодой (21★) [U] | глубина из Stage 1 |

| Текстуры | проекция из лучших кадров (угол, расстояние, резкость, без масок персонажей), xatlas UV, seam blending | — | CPU | — |
| Плохо видимые объекты | **TRELLIS.2 через trellis-mac** (MPS, ~5 мин/объект, PBR-бейк через Metal) | MIT, но RMBG-2.0 CC BY-NC → заменяем фон на маску SAM 3 [V] | ✔ community-порт [V] | SF3D / SPAR3D (Stability Community, MPS experimental, Metal-бейкер) [V] |

Hunyuan3D не беру основным: текстурирование на Mac упирается в CUDA-растеризатор [U], плюс территориальная оговорка лицензии.

Где splats, где mesh: **mesh** — всё, с чем взаимодействуют персонажи и свет (структура, мебель, пол); **splats** — задник для фотореализма рендера с исходных камер и дальние мелкие детали (полки, декор), которые плохо мешуются. В Blender 5.2 splats через аддон KIRI 3DGS Render (GPL-2, поддерживает 5.2) [V]; в 5.3 (ожидается 2026-11) — нативный импорт [U].

### Stage 4 — inference of unseen
- Style card (VLM по 10–20 лучшим кадрам) → JSON: палитра (k-means в Lab по немаскированным пикселям — числа, не VLM), материалы, эпоха/стиль, тип освещения, стилизация (toon/painterly).
- Поиск дыр: неосвещённые кадрами тексели (карта покрытия в UV), незамкнутые области коробки комнаты, объекты, обрезанные кадром.
- Достройка:
  - стены/пол/потолок: рендер недостающего вида из Blender → **FLUX.1 Fill через mflux** (MLX, маска) или Qwen-Image-Edit-2511 → обратная проекция в текстуру; промпт = style card + соседние видимые участки как референс;
  - обратные стороны объектов: TRELLIS.2 генерирует полный объект → видимые участки перетекстурируются из кадров, невидимые остаются сгенерированными;
  - ComfyUI (:8188) — второй бэкенд через `/prompt` + `/ws` + `/view` (адаптер `backends/comfy.py`), чтобы можно было подставлять свои workflow.
- Каждый элемент: `source: "inferred"`, `basis: [object_ids, frame_ids]`, `generator`, `prompt`, `seed`, `mask_path` → можно перегенерировать одной командой.

Лицензии: FLUX.1 Fill dev — некоммерческая [U]; Qwen-Image-Edit и FLUX.2-klein-4B — Apache.

### Stage 5 — verification loop
- Рендер: Blender 5.2 headless (`Blender -b -P`), EEVEE для цикла, Cycles для финала; разрешение исходных кадров (опция `--verify-scale 0.5` для скорости).
- Метрики per-frame, только по видимым немаскированным пикселям: LPIPS (torchmetrics), SSIM/PSNR, DINOv2-cosine (Apache; DINOv3 — gated), IoU масок объектов, ошибка глубины (AbsRel против Stage 1).
- VLM-сверка кадр↔рендер → список расхождений с привязкой к object ID (через сопоставление масок).
- Оптимизация: CMA-ES (`cmaes`, MIT) по позе/масштабу/повороту объектов и экспозиции; loss = IoU масок + глубина + LPIPS; inferred-области исключены из loss. Mitsuba 3 `metal_ad_rgb` [V: arm64 wheels, Metal-варианты с 3.9.0] — опционально для градиентного уточнения силуэтов. Бюджет итераций и лог сходимости.
- Отчёт: `report.html` (кадр / рендер / разница / метрики, сортировка по худшим).

### Stage 6 — export
- bpy-скрипт внутри Blender.app: коллекции `Structure`, `Props_observed`, `Props_inferred`, `Splats`, `Cameras` (одна камера на план, анимированная по кадрам; метаданные плана), `Lights`.
- `.blend`, `.glb`, опционально `.usdz/.usd`; `manifest.json` (схема версионируется, pydantic).
- `examples/place_character.py`: glb персонажа → raycast к полу в точке (x, y) → рендер с камеры кадра N.

## 3. Структура репозитория

```
sceneforge/
  pyproject.toml, uv.lock, third_party.lock.toml, Makefile
  scripts/doctor.sh, scripts/setup_mac.sh
  src/sceneforge/
    cli.py                # typer: ingest|masks|geometry|segment|reconstruct|infer|verify|export|run|status
    core/{cache.py, stage.py, device.py, profiling.py, manifest.py, config.py}
    stages/{s0_ingest, s0b_masks, s1_geometry, s2_segment, s3_reconstruct, s4_infer, s5_verify, s6_export}.py
    backends/{vlm_openai.py, sam3_mlx.py, mapanything.py, colmap.py, brush.py, trellis.py, mflux.py, comfy.py, blender.py, remote_ssh.py}
    blender_scripts/{assemble.py, render_cameras.py, place_character.py}
  configs/default.toml
  work/<scene>/<stage>/...     # в .gitignore
```

Контракт этапа: `work/<scene>/<stage>/_stage.json` = {input_hash (хэш входных файлов + конфига этапа + версии кода), started, finished, wall_time, peak_rss, peak_mps_mem, device, outputs}. Совпал хэш → пропуск; `--force` → пересчёт; частичные результаты пишутся во временную папку и атомарно переименовываются. Ничего вне `work/` не пишется и не удаляется.

`--device {mps,cpu,remote}`: при `cpu` для тяжёлых этапов выводится оценка времени и запрашивается подтверждение (`--yes` для автоматического режима).

Сцена из нескольких клипов: `sceneforge run "Room RUMI.mkv" "Room RUMI 2.mkv" --scene rumi_room`.

## 7. Принятые решения (после согласования)

- **Лицензии:** `license_profile = "noncommercial"` по умолчанию (веса MapAnything CC-BY-NC и т. п.). Переключатель `commercial` есть в конфиге; таблица замен компонентов — `docs/research/README.md`.
- **Окружения:** три изолированных env вместо одного (конфликт opencv 4.10 у MapAnything против ≥4.12 у mlx-vlm). Тяжёлые модели — отдельные процессы-воркеры (`src/sceneforge/workers/`), оркестратор меряет их память.
- **Stage 0b до геометрии:** маски персонажей через SAM 3.1 (MLX), `predict_multi` — один проход backbone на кадр для всех промптов.
- **Масштаб перенесён в Stage 2** (нужны сегменты). Якорь принимается только если объект хотя бы раз виден целиком (маска не касается края кадра и маски персонажа); размер — максимум по таким видам. Один якорь — принимается с предупреждением; ноль или противоречивые — вопрос пользователю (или метрика MapAnything при `--yes`).
- **Боксы объектов:** вертикальные, поворот — минимальная площадь с привязкой к осям комнаты.
- **COLMAP-refine** в MVP не включён; добавим, если MapAnything не справится с реальными клипами.
